# Project development notes

- At the start of each session, read `docs/README.md` and `docs/WORKFLOW.md`. Documentation is kept in `docs/`; this root `AGENTS.md` remains here so project instructions are discovered automatically. Read the relevant documents and plans listed in the index before working on those areas.
- Source files supplied for future database imports belong in `../private/source-data/`, outside the public web root and this source repository. Read `docs/SOURCE_DATA.md` before preparing an import; uploading a file does not authorize importing it.
- After creating a new public web file, verify that the web server can read it. Public PHP pages and other served assets should normally use mode `664`, matching the existing files in this project; run `chmod 664 <file>` and confirm with `ls -l`.
- When adding a new image-upload section, pre-create its `filestore/images/<section>/<size>` directories and verify that the PHP/web user can write to them. This deployment's established upload folders use group/setgid or shared-write permissions; test the actual upload path rather than assuming `mkdir()` can create it at runtime.
- Before any deployment, read `docs/DEPLOYMENT.md`. Before deploying Ride Report galleries to another environment, Codex must follow its gallery checklist. Do not mark the deployment complete until the live `news` image directories exist, have shared-write permissions, and pass the documented writability checks. Empty Git-tracked directories alone do not guarantee correct live permissions.
- Keep reusable application source changes flowing in one direction: make, test, and commit PHP/JavaScript/CSS and shared migration-file corrections on the development environment, then push and pull them into staging with `git pull --ff-only`. Staging may receive environment-specific database data/schema operations after backups, but Codex must not make reusable source-code fixes directly on staging. If a staging migration reveals a required source correction, stop, report it, apply and commit the correction on development first, then pull it into staging. Do not instruct staging Codex to amend shared source files as part of a data-only migration.
